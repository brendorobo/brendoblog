"Did this binary run?" is one of the first questions in almost every Windows investigation.
No single artifact answers it on its own, but several of them together usually do.

## The cheat sheet

| Artifact | Location | Proves execution? | Notable data |
| --- | --- | --- | --- |
| Prefetch | `C:\Windows\Prefetch\*.pf` | Yes | Run count, up to 8 last run times (Win8+), files referenced |
| Amcache | `C:\Windows\AppCompat\Programs\Amcache.hve` | Presence, often execution | Full path, SHA1, publisher |
| Shimcache | `SYSTEM\...\Control\Session Manager\AppCompatCache` | **No** on Win10+ | Path, file last-modified time, order |
| BAM | `SYSTEM\...\Services\bam\State\UserSettings\{SID}` | Yes | Last execution time per user |
| UserAssist | `NTUSER.DAT\...\Explorer\UserAssist` | Yes (GUI launches) | ROT13 names, run count, focus time |

<Callout type="warn" title="classic trap">
Shimcache entries show a file *existed* and was seen by the OS. On modern Windows that alone
doesn't prove it ran. The timestamp is the file's **last modified** time, not when it ran.
Pair it with Prefetch, BAM or Amcache before you claim execution.
</Callout>

## Parsing them

Eric Zimmerman's tools make this fast. Point each one at the artifact and dump to CSV, then
pull everything into Timeline Explorer.

<Cmd host="forensic-ws" cmd="PECmd.exe -d C:\Cases\E01\Windows\Prefetch --csv C:\Cases\out" />
<Cmd host="forensic-ws" cmd="AmcacheParser.exe -f C:\Cases\E01\Windows\AppCompat\Programs\Amcache.hve --csv C:\Cases\out" />
<Cmd host="forensic-ws" cmd="AppCompatCacheParser.exe -f C:\Cases\E01\Windows\System32\config\SYSTEM --csv C:\Cases\out" />

## Takeaways

1. Use several artifacts together. One artifact is a lead; three that agree are a finding.
2. Know what each timestamp *means* before you put it on a timeline.
3. Next note: **lateral movement artifacts** (4624/4648, RDP bitmap cache, PsExec traces).
